## Что действительно выполнено

- `npm run build`: успешно, 1751 модуль; первоначально проверенная расширенная сборка содержала CSS около 29 KB и JS около 286 KB. После этого frontend-agent внёс дополнительные исправления; parent выполняет финальную сборку.
- Подготовлены `tests/support/browser-prepare.js` и существующий `tests/support/browser-batch.js` для проверки реального React → HTTP-контракт → Fastify → SQLite в среде без TCP-портов.
- Из нового `dist` успешно сформирован `/tmp/kupala-browser-init.js`.
- Проведён исходный просмотр новых форм и страниц для планирования сценариев. Замечание о выборе даты кампуса вне загруженной недели передано frontend-agent; он связал выбор даты с новой неделей.

## Почему браузерная проверка заблокирована

1. Виртуальный Playwright MCP не смог открыть браузер: `Browser is already in use for .../mcp-chrome-e0680c7, use --isolated`. Ошибка возникла до выполнения Playwright-функции и до загрузки приложения.
2. Штатные `browser_close` и создание вкладки с отдельным `isolatedContext` вернули ту же ошибку инициализации глобального профиля. Повторных циклов запуска не выполнялось.
3. Дополнительно проверен безопасный независимый headless-процесс: Playwright-core из уже имеющегося npm-кэша, Chromium, новый временный профиль, remote-debugging-pipe без TCP. Процесс закрылся с сообщением Crashpad `setsockopt: Operation not permitted`.

Пользовательский Chrome и его вкладки не открывались и не изменялись. Системные процессы не завершались, профиль MCP не удалялся, повышения прав и обхода ограничений не было. Новых попыток входа на портал и работы с университетскими учётными данными не выполнялось.

## Воспроизводимый способ после восстановления браузера

1. Выполнить `npm run build`.
2. Выполнить `node tests/support/browser-prepare.js /tmp/kupala-browser-init.js`.
3. Запустить эту функцию через доступный виртуальный Playwright. Она обслуживает `dist` на тестовом адресе `http://kupala-app.test/`; API-запросы складываются в `page.__qaPending`.
4. Сериализовать только `{id,request}` из очереди в защищённый временный JSON. Выполнить `node tests/support/browser-batch.js input.json output.json /tmp/kupala-expansion-ui.sqlite`.
5. Вернуть ответы через `route.fulfill` с HTTP-статусом, заголовками, cookie и телом ответа. Для отменённых запросов обработать отмену отдельно. Повторить, пока очередь не опустеет.
6. Проверить сценарии из таблицы. Использовать только тестовые профили и демо. Сеть Node в текущей песочнице недоступна, поэтому первая реальная загрузка справочника может дать ожидаемую ошибку; демо должно открываться явным действием.
7. Сохранить реальные screenshot-артефакты обоих desktop-размеров и наблюдения. Только после этого формировать passing evidence record и запускать checker.

Мост использует настоящий `buildApp` и временную SQLite; бизнес-логика не подменяется. Прямое TCP-соединение браузер → локальный сервер этим способом всё равно не проверяется и требует обычной локальной проверки при доступных портах.
