# Desktop UI и доступность: статический аудит

**Область:** дизайн A, desktop UI; модалки, навигация и формы Kupala Hub, разделы expansion и чат ассистента. Основа — статический просмотр исходников `web/src`; ниже отдельно отмечены наблюдения координатора в виртуальном браузере. Это не заявление о WCAG-сертификации.

## Важные замечания

1. **P2 — при 400% увеличении может появляться горизонтальный скролл всей страницы.** `body { min-width: 1080px }` сохраняет широкую страницу, даже если zoom сужает CSS viewport [styles.css:3](../../web/src/styles.css#L3). Проверить и при подтверждении дать основным колонкам сжиматься/перекладываться; горизонтальный скролл оставить только для таблиц/недельной сетки. Обычный мобильный layout вне этой desktop-проверки.

2. **Важно — нативные модалки открываются, но исходный фокус теряется при Escape.** Координатор подтвердил в браузере `:modal=true`; при открытии формы создания и редактирования задачи фокус оказывается на кнопке «Закрыть», хотя поле имеет `autoFocus`, а после Escape `activeElement` становится `BODY`, а не кнопкой-открывателем. Порядок элементов виден в [App.jsx:11](../../web/src/App.jsx#L11) и [App.jsx:25](../../web/src/App.jsx#L25). Явно фокусировать основное поле после открытия и сохранять/восстанавливать ссылку на открывшую кнопку после закрытия.

3. **Важно — вкладки с ARIA-ролями не переключаются стрелками.** Координатор проверил вкладку «Оценки»: ArrowRight оставляет фокус и `aria-selected=true` на ней; обычный Tab проходит дальше. Компонент задаёт `role="tab"` и `aria-selected`, но не реализует стрелочную навигацию [common.jsx:10](../../web/src/expansion/common.jsx#L10); он используется также во вложенных вкладках финансов [Learning.jsx:12](../../web/src/expansion/Learning.jsx#L12). Реализовать ожидаемое перемещение по вкладкам стрелками и один Tab stop, либо представить это как набор обычных кнопок и убрать tablist/tab роли.

4. **Важно — часть вторичного текста ассистента имеет низкий контраст.** Стили задают, например, время сообщений `#96a0b1` 10px на белом (расчётный контраст 2.64:1) [assistant.css:39](../../web/src/assistant/assistant.css#L39), placeholder `#a1aaba` на `#fbfcfe` (2.28:1) [assistant.css:60](../../web/src/assistant/assistant.css#L60), а для самого placeholder — цвет в [assistant.css:62](../../web/src/assistant/assistant.css#L62). Это ниже 4.5:1 для обычного текста. Затемнить эти цвета, сохранив существующую палитру; при повторной проверке учитывать фактический фон градиента. Расчёты статические, браузерный рендер не проверен.

5. **Полезно — при смене страницы фокус не направляется в новый контент.** Навигация обновляет состояние страницы/хэш [App.jsx:45](../../web/src/App.jsx#L45), основной landmark остаётся на месте [App.jsx:62](../../web/src/App.jsx#L62), а новый `h1` не получает фокус. При переходе клавиатурой пользователь остаётся в боковом меню; скринридер может не сообщить о смене основного содержимого. После перехода можно направлять фокус на заголовок страницы или ненавязчиво объявлять название нового раздела. Это рекомендация по SPA-навигации; одной статической проверки недостаточно, чтобы заявить нарушение конкретного критерия WCAG.

6. **Проверить — фактическую область нажатия у стрелок выбора даты.** У стрелок полосы дат задано `min-width:22px`, при общей минимальной высоте кнопок 34px [styles.css:5](../../web/src/styles.css#L5). Одного этого недостаточно, чтобы подтвердить несоответствие SC 2.5.8: нужно проверить итоговую hit area и исключение по расстоянию до соседних целей. Если исключение не выполняется, увеличить область клика, сохранив визуальный размер иконки.

## Проверить в браузере

- **Наблюдение в снимках 1440×1000, переданное координатором:** нижние два пункта боковой навигации скрыты за прокруткой `.expanded-nav`, но видимого индикатора прокрутки нет. CSS подтверждает `overflow-y:auto` и стилизацию полосы прокрутки [expansion.css:2](../../web/src/expansion.css#L2). Проверить обнаружимость прокрутки мышью, клавиатурой и скринридером; рассмотреть постоянно видимую подсказку/градиент или компактнее разместить группы меню.
- Для вкладок уже проверено: ArrowRight не перемещает фокус и выбор, Tab проходит на следующий control. После исправления проверить Left/Right и озвучивание выбранной вкладки.
- Проверить восстановление фокуса и стартовую точку для остальных диалогов, включая редактор материала; наблюдение выше подтверждено для форм создания/редактирования задачи. В диалогах используются `showModal()` [App.jsx:11](../../web/src/App.jsx#L11), [common.jsx:15](../../web/src/expansion/common.jsx#L15).
- Проверить реальную различимость глобального focus ring на кнопках/ссылках и вложенной прокрутке списка преподавателей. У поля ассистента вычисленные стили `outline:none`, тень `rgba(49,89,199,.1)` толщиной 3px и граница `rgb(169,188,233)`; координатор оценил контур как слабый, но не отсутствующий. Это кандидат на улучшение, не подтверждённый блокер.
- Координатор проверил 13 экранов при 1280×900: горизонтального переполнения не было. Переполнение при 400% zoom остаётся отдельной непроверенной гипотезой из-за `min-width` на `body`.
- Проверить читаемость текста после 200% увеличения, контраст состояний загрузки/ошибок и видимость чата при увеличенном системном шрифте. Малый размер шрифта сам по себе не доказывает несоответствие WCAG, но текст 10–12px встречается часто, включая подписи и статусы [assistant.css:50–56](../../web/src/assistant/assistant.css#L50).
- Проверить, что добавление ответа в `role="log"` и появление статуса занятости не приводит к повторным или чрезмерно частым объявлениям скринридером [AssistantPage.jsx:87–89](../../web/src/assistant/AssistantPage.jsx#L87).

## Короткий чеклист удобства форм

- [x] Координатор проверил основные input/select/textarea на 13 экранах: у всех есть label или accessible name, включая пустое демо. Checkbox передачи контекста имеет видимую подпись [AssistantPage.jsx:99](../../web/src/assistant/AssistantPage.jsx#L99).
- [x] Обязательные поля в аккаунте, задаче и материале используют нативный `required`; дата/время и URL имеют корректные типы.
- [x] Ошибки сервера показываются как `role="alert"`; обычные сообщения об успехе выводятся как status/toast.
- [ ] Сообщения ошибок формы пока общие, не связаны с конкретными полями через `aria-describedby`/`aria-invalid`; для серверной ошибки это приемлемо, для ошибок конкретного поля стоит добавить связь и подсказку исправления.
- [ ] У счетчика сообщения ассистента нет программной связи с textarea, а подпись клавиши Enter находится отдельно от поля [AssistantPage.jsx:92–93](../../web/src/assistant/AssistantPage.jsx#L92). Добавить счетчик/инструкцию в `aria-describedby` и объявлять обновление счётчика ненавязчиво, если это полезно пользователю.
- [x] Положительные значения `tabIndex` и самодельные div-кнопки в проверенном UI не обнаружены; большинство действий реализовано нативными кнопками/ссылками.

## Критерии, затронутые замечаниями

Потенциально затронуты WCAG 2.2 AA: 1.4.3 Контраст (минимум), 1.4.10 Reflow и 4.1.2 Имя, роль, значение. Визуальная достаточность фокуса и размер целей требуют проверки итогового рендера/геометрии; конкретное нарушение по ним не заявляется. Клавиатурная модель tablist сверяется с ARIA Authoring Practices. Это аудит отдельных участков, не проверка полного соответствия.
