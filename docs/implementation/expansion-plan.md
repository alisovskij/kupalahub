# Расширение Kupala Hub: архитектура и договорённости

22.11.2026. Основание: пользователь поручил добавить функции из `docs/grsu-data-catalog.md`, сохранить выбранный дизайн A и распределить работу между агентами. Backend — JavaScript; платформа — десктопный веб. ИИ и дальнейшие попытки подключения SSO не входят в этот этап.

Это проектный контракт для параллельной реализации, а не заявление о готовности перечисленных возможностей. Фактическая приёмка фиксируется отдельно.

## Текущее состояние и решение

Сохраняем React/Vite + Fastify + SQLite, cookie-сессии, CSRF, `live/demo` и существующие маршруты. Не добавляем Redis, PostgreSQL или микросервисы ради количества экранов. Основной долг — несколько очень длинных строк `App.jsx` и `app.js`, смешивающих формы, представления, данные и маршруты. Расширение делаем новыми небольшими модулями с минимальными точками подключения.

Разделы имеют три класса источника:

1. **Реальные публичные данные:** расписание, преподаватели, связанные группы и адреса; занятия сессии извлекаются из опубликованного расписания.
2. **Собственные данные:** профиль Kupala Hub, задачи, заметки, приглашения, сообщества и объявления. Они не называются университетскими подтверждениями.
3. **Закрытые неподключённые данные:** успеваемость, аттестация, пропуски, университетский профиль, платежи, приказы и Moodle. В live — объяснение отсутствия подключения без выдуманных строк. В demo — детерминированные примеры с постоянной маркировкой.

## Общий контракт ответа

Новые коллекции возвращают `items`, `source`, `status`, `fetchedAt`, `stale` и, где требуется, `coverage`. Существующий контракт расписания не ломаем: остаётся `days`, `subgroups`, `changes`.

- `source`: `grsu | self | demo | unavailable`.
- `status`: `ready | partial | disconnected`.
- `fetchedAt`: ISO-время либо null для неподключённого источника.
- `stale`: boolean, предупреждение отдельным `warning`.
- `coverage`: фактический период, просмотренные группы/снимки, ограничения полноты.
- Нет доступа к модулю: HTTP 200 + `status:disconnected`, пустая коллекция и сообщение. Это не ошибка сети и не повод незаметно загрузить demo.
- Ошибка источника без снимка: 502. Невалидный запрос: 400. Нет своей сессии: 401. Нет прав на объект: 404 для его сокрытия.
- Все даты — ISO `yyyy-MM-dd`, время — Europe/Minsk, ID преподавателя допускает отрицательное число, в транспортном формате ID — строки.
- Недоступная оценка/сумма — null, а не 0. Неподтверждённый допуск — `unknown`, а не `denied`.

## API для независимой разработки

Рекомендуемый набор; route-agent фиксирует точное имя в API-документе перед подключением UI.

| Маршрут | Вход | Ответ / правила |
| --- | --- | --- |
| GET `/api/teachers` | mode, q до 120 символов | items: id, fullName, post, email, phone, description; фильтрация по каталогу, пустые контакты допустимы |
| GET `/api/teachers/:id/schedule` | mode, start-понедельник | Нормализованный недельный `days`, у занятия массив `groups` (бывает пустым); источник `getTeacherSchedule`. Имя преподавателя берём из выбранной записи каталога: в ответе занятия его может не быть |
| GET `/api/exams` | mode, groupId, start-понедельник, weeks 1–6 | items: date/start/end/title/type/room/address/teacher/subgroup; фильтрация по типу, coverage со списком доступных недель |
| GET `/api/campus` | mode, groupId, start-понедельник | Корпуса/помещения, наблюдаемые только в выбранном расписании; coverage обязателен. Нет глобального обхода всех групп |
| GET `/api/learning` | mode; tab из allowlist | `grades`, `attestation`, `absences`, `finance`, `orders`, `materials`; live disconnected, demo по общей модели ниже |
| GET `/api/profile` | собственная сессия | Собственное имя/email и настройки, сведения об университетском профиле отдельно как disconnected |
| PUT `/api/profile` | name | Меняет только имя Kupala Hub. Университетское ФИО и принадлежность не утверждает |
| GET/PUT `/api/preferences` | собственная сессия; поля ниже | Настройки представления/уведомлений отдельно от старой схемы выбора группы |
| GET `/api/notifications` | scope, limit 1–100, cursor | Личные локальные напоминания и события сравнения снимков; ключ источника и readAt |
| PATCH `/api/notifications/:id` | read:true | Только своя запись, повторное действие безопасно |
| GET/POST `/api/communities` | scope; POST title, groupId? | Создание частного сообщества, организатором становится создатель, а не «официальным старостой» |
| POST `/api/communities/join` | inviteCode, scope | Приглашение с достаточной случайностью, лимиты попыток; не перечисляет чужие сообщества |
| GET `/api/communities/:id` | scope | Только участникам; имя/роль/дата вступления, без email, скрытых идентификаторов и университетских сведений |
| POST `/api/communities/:id/invite` | scope | Организатор создаёт или обновляет приглашение; хранить hash секрета, сырой код показывать только при выдаче |
| GET/POST `/api/communities/:id/posts` | scope; POST title/body | Объявления, авторство. Создаёт организатор; читает участник |
| DELETE `/api/communities/:id/posts/:postId` | scope | Только организатор; ID объявления привязан к этому сообществу |
| GET/POST `/api/communities/:id/tasks` | scope; title/subject/dueDate | Общее задание создаёт организатор, выполнение индивидуальное |
| PUT `/api/communities/:id/tasks/:taskId/completion` | scope; done | Меняет только состояние текущего участника, не всей группы |

Необязательно реализовывать курсорную пагинацию для маленького первого списка: допустим фиксированный limit и явное ограничение. Не предоставлять неограниченные коллекции или возможность скачивать весь roster всем зарегистрированным.

Для сессии можно сделать шесть запросов уже проверенного недельного метода последовательно через существующую очередь. Не предполагать поддержку произвольного многомесячного периода. Загружать по запросу, использовать кэш, не обновлять шесть недель на каждое движение фильтра. Частичное получение — `partial`, а не «сессии нет».

Для кампуса не нужен новый upstream API: производный индекс `address+room`. «Свободная» означает лишь отсутствие занятий в явно указанном покрытии. Самостоятельное обращение к картам — обычная внешняя ссылка с корректным кодированием адреса, без придуманных координат и времени пути.

### Уточнение распределения после запуска агентов

Backend-agent владеет только `server/expansion.js`, `server/expansion-demo.js`, `tests/expansion.test.js`. Родитель регистрирует `registerExpansion`, изменяет app.js/database.js и реализует публичные маршруты. Для закрытых модулей договорённый маршрут — `/api/learning?mode&tab`, профиль — GET/PUT `/api/profile`, настройки — GET/PUT `/api/preferences`. Собственные ссылки на материалы — CRUD `/api/materials?scope`, отдельно от неподключённых университетских материалов.

Подтверждён контракт сообщества: `/api/communities` list/create, `/api/communities/join`, `/api/communities/:id` workspace, `/:id/posts`, `/:id/tasks`, `/:id/polls`, `/:id/polls/:pollId/vote`. Scope live/demo передаётся явно; роль owner означает организатора приложения. Поддержка отдельных invite/completion endpoints из таблицы выше — проектная рекомендация; до подтверждения backend-agent UI не должен их вызывать. Точные request/response структуры workspace берутся из реализации backend-agent, не выдумываются фронтендом.

Текущая повторная проверка 22.11.2026: каталог преподавателей содержит 1107 записей; число не фиксировать в UI. В teacher schedule найдено событие «Семинар» с пустым groups и без teacher — это корректный ответ.

## Модели закрытого демо

Модели являются внутренним форматом Kupala Hub, не схемой действующих закрытых API. Поля заполняются только в демонстрации; неизвестная официальная детализация не выдаётся за исследованную.

| Раздел | Минимальные поля |
| --- | --- |
| profile | displayName, avatarInitials, educationalGroups[{type,title}]; отметка demo |
| grades | id, semester, subject, assessmentType, resultText, grade:null/number, date |
| attestation | id, semester, subject, periodTitle, resultText; без выдуманного официального рейтинга |
| absences | id, date, amount, unitLabel, reason; unitLabel явно демонстрационный |
| finance | начисления и платежи как два отдельных списка: id, date, purpose, amount, currency; баланс только из совместимых demo-строк |
| orders | id, date, number, title, summary; без кнопки PDF, если файла нет |
| materials | courseId/title, sections[{title,resources[{id,type,title,url?}]}], assignments[{id,title,dueDate,submissionStatus}]; demo не принимает официальные работы |

Стипендия, допуск, официальный рейтинг, задолженность общежития не получают фальшивый live-провайдер. Если дизайн содержит их как исследовательские показатели, он явно подписывает «пример», а тексты не сообщают об официальном решении университета.

## Хранилище

Изменения БД — в отдельной миграции с `PRAGMA user_version` либо собственной таблицей migrations; повторный старт не должен удалять существующих пользователей/tasks/cache.

- `preferences(user_id PK/FK, json, updated_at)` — theme `light|dark|system`, defaultView `week|day`, reminderMinutes 0–120, inAppReminders boolean. Эти поля не расширяют валидатор старого `/api/settings` неявно.
- `communities(id PK, scope, title, group_id nullable, owner_id FK, created_at)`.
- `community_members(community_id FK, user_id FK, role CHECK owner/member, joined_at, PRIMARY KEY community_id/user_id)`.
- `community_invites(id PK, community_id FK, token_hash UNIQUE, expires_at, revoked_at)`.
- `community_posts(id PK, community_id FK, author_id FK, title, body, created_at, updated_at)`.
- `community_tasks(id PK, community_id FK, author_id FK, title, subject, due_date, created_at)`.
- `community_completions(task_id FK, user_id FK, done, updated_at, PRIMARY KEY task_id/user_id)`.
- `notifications(id PK, user_id FK, scope, kind, dedupe_key, title, body, target, created_at, read_at, UNIQUE user_id/scope/dedupe_key)`.

Минимальные индексы: community_members(user_id), posts/tasks(community_id,created_at), notifications(user_id,scope,created_at). Все запросы параметризованы. Проверка владельца/участника выполняется перед чтением, а scope участвует в каждом доступе. Создание community+membership и join выполняются транзакционно. Удаление/ротация приглашения — отдельное явное действие.

Закрытые demo-записи можно генерировать неизменяемо по `userId+scope`: не требуется сохранять фиктивную академическую БД. Демонстрация не должна содержать ФИО или фото реальных людей из исследованных скриншотов.

## Дизайн и состояния

Предпочтительная навигация: ежедневное ядро «Сегодня / Расписание / Задачи», затем группа «Учёба» с «Сессия / Успеваемость / Материалы», затем «Университет» с «Преподаватели / Кампус / Сообщество»; профиль, финансы, приказы и настройки доступны через профиль/вторую группу навигации. Не помещать 14 равнозначных кнопок в один длинный список.

На каждом экране: короткий заголовок, основной следующий шаг, источник и актуальность. Для closed live пустое пространство должно объяснять, почему данных нет, и давать «Посмотреть пример», не навязывая ввод пароля. Состояния загрузки/ошибки/пустого периода/частичного покрытия/demo различаются.

Профиль разделяет «Мои настройки Kupala Hub» и «Данные университета». Сообщество показывает «организатор» и «участник», не назначает старосту по выбору группы. Уведомления — центр внутри приложения, а не обещание фонового Web Push. Переключение demo/live должно быть заметно во всей оболочке и не переносить учебные/сообщественные данные между областями.

## Последовательность и приёмка

1. Зафиксировать API и визуальные состояния. Параллельно — публичный адаптер, private/demo/community backend и страницы по согласованному контракту.
2. Интегрировать оболочку и данные. Проверить сохранение прежних задач и существующих тестов.
3. Backend tests: signed teacherId, nullable contact, source metadata, exam filter, partial weeks, campus coverage, отсутствие закрытых вызовов в live, demo isolation, membership/owner checks, приглашения, индивидуальное выполнение, dedupe уведомлений, сохранность миграции.
4. Браузерные journeys: группа → преподаватель → неделя; сессия с пустым периодом; live academic disconnected → demo → обратно; создание сообщества → приглашение со второго аккаунта → объявление/общее задание; уведомление read; настройки после перезапуска; старые CRUD задач.
5. Визуальная проверка 1280×900 и 1440×1000, длинные названия и комиссии, клавиатура/Escape/фокус, отсутствие переполнения страницы. Mobile отложен.
6. Независимый review и исправление критичных замечаний; npm test и npm run build. Документировать, где реальная интеграция, где собственные данные, где демонстрация, и какие варианты ещё не проверены.

## Компромиссы

SQLite подходит для локального развёртывания и нескольких пользователей, но синхронные операции и один файл ограничивают масштабирование. В этом этапе не обещаем распределённый сервис. Живой публичный API не имеет подтверждённого SLA; остаются очередь с бережным интервалом, кэш, таймаут и старый снимок. Частные интеграции не являются блокером для демонстрации их UX, но остаются блокером для заявления «получаем реальные оценки и финансы».
