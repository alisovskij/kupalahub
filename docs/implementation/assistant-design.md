## Польза

План дня между занятиями; ближайшие дедлайны и просрочки; объяснение приоритетов; разбивка задачи; подготовка к паре/экзамену; поиск по собственным ссылкам и заметкам. Агент видит только данные текущего пользователя/режима. Закрытые данные ГрГУ остаются неподключёнными. Материалы читаются как данные; агент не открывает произвольные URL и не получает shell/SQL.

## Границы

Браузер → Fastify (сессия/CSRF/согласие) → Python (межсервисный секрет) → DeepSeek. Python вызывает только определённые инструменты Fastify по короткому подписанному разрешению, привязанному к пользователю, scope, времени и запросу. Пароли, cookies, email и grant не отправляются модели. Python не подключается к SQLite. Общая история хранится в Node по владельцу/scope и удаляется отдельно.

Перед первой отправкой пользователь явно разрешает передачу задач/расписания/личных заметок DeepSeek. Каждый запрос требует shareContext:true. Контекст ограничен по размеру и сообщает период/усечение. Инструменты обновляют чтение на запрос; пользовательские тексты не считаются инструкциями. Ссылки на источники формируются инструментами, а не доверяются модели.

Все изменения задач проходят две стадии: модель предлагает конкретное действие → Node сохраняет pending action на 10 минут → пользователь подтверждает → проверяются владелец, scope, актуальность исходной задачи → атомарная запись. Повторное подтверждение идемпотентно. Чат не выполняет действие сам. Ошибка/обрыв чата отменяет новые предложения. Параллельные диалоги одного пользователя/режима сериализуются, лимиты запросов и истории ограничивают расход.

## Контракт

- Node /api/assistant/status, /history GET DELETE?scope, /chat POST {message,scope,shareContext:true}, /proposals/:id/confirm POST {scope}.
- Python /health GET auth, /chat POST auth {message,history,context,grant}, ответ {answer,sources,proposals,usage}.
- Callback /internal/assistant/tools POST {name,arguments}; Authorization и X-Agent-Grant обязательны; разрешение только на активный запрос, без client userId.
- Инструменты get_tasks, get_schedule(start), search_materials(query), propose_task, propose_task_update. Никаких прямых инструментов записи.
