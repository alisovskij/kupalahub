# Каталог данных для развития Kupala Hub

Дата исследования: 16.11.2026. Основание для дальнейших решений после приостановки проверки закрытого портала. Разработка интеграции с SSO и новые попытки авторизации в рамках этого исследования не выполнялись. ИИ исключён из текущего этапа по решению пользователя.

## Как читать подтверждения

- **API проверен** — ранее получен реальный ответ публичного метода ГрГУ.
- **Экран/описание** — данные показаны на опубликованном экране другого приложения или явно заявлены разработчиком. Это подтверждает возможность продукта, но не доступность интеграции для нас.
- **Пункт меню** — виден раздел, но его содержимое и поля не раскрыты. Не считаем это успешным чтением данных.
- **Гипотеза** — потенциальная функция платформы; для конкретного аккаунта ГрГУ не проверена.

Публичные картинки и описания могут относиться к старым версиям. Приложения не устанавливались, закрытые личные кабинеты не просматривались. Наличие функции у официального клиента не означает наличие публичного API. Полный перечень закрытых методов и форматы ответов неизвестны.

## 1. Общедоступные данные: основа текущего приложения

| Данные | Поля / содержание | Основание | Состояние Kupala Hub |
| --- | --- | --- | --- |
| Формы обучения | ID, название | getDepartments, API проверен | Подключено |
| Факультеты и подразделения | ID, название | getFaculties, API проверен | Подключено |
| Учебные группы | ID, название, выбор по форме/факультету/курсу | getGroups, API проверен | Подключено |
| Занятия группы | Дата, начало/конец, дисциплина, тип | getGroupSchedule, API проверен | Подключено |
| Место занятия | Адрес, аудитория; поля бывают пустыми | Тот же API | Подключено |
| Преподаватель пары | ID, ФИО/строка комиссии, должность | Тот же API | В карточке пары |
| Подгруппы занятий | ID и название; общие и параллельные занятия | Тот же API | Фильтр подключён. Выбор студента пока ручной |
| События сессии | Экзамен, зачёт, консультация, защита, дата/время/место | Реальные примеры API; приложения расписания | Видны в общем расписании; отдельного раздела сессии нет |
| Справочник преподавателей | ФИО, должность, иногда email/телефон и другие контакты | getTeachers, API проверен | Отдельный справочник пока не подключён |
| Расписание преподавателя | Занятия, связанные группы, иногда численность группы | getTeacherSchedule, API проверен | Отдельный экран пока не подключён |
| ID студента по известному логину | Код клиента использует id из ответа | RemoteUsers.kt в grsu-notifications | Не проверяли на аккаунте; не использовать как аутентификацию |

Проверенные URL, реальные поля и крайние случаи приведены в [аудите API](data-feasibility-audit.md). Горизонт публикации и полнота всех групп не установлены.

## 2. Персональные данные: ориентир по MyGRSU

Основание таблицы — [карточка и скриншоты MyGRSU](https://play.google.com/store/apps/details?hl=ru&id=com.grsu.mygrsu). Они подтверждают отображение следующих категорий, но способ получения закрытых данных для Kupala Hub неизвестен.

| Категория | Что подтверждено | Что пока нельзя утверждать |
| --- | --- | --- |
| Профиль | ФИО, фотография, название группы на главной | Полный набор паспортных, контактных и учебных полей |
| Пропуски | Дата, количество, текст причины | Единицы количества, детализация по каждой паре и правила уважительности |
| Промежуточная аттестация | Отдельный пункт меню; описание заявляет аттестацию | Точный формат показателей и периодов |
| Успеваемость | Выбор семестра, дисциплины, статус «зачтено», подпись аттестации | Полная шкала отметок, средний балл, официальный рейтинг |
| Плата за обучение | Пункт меню | Начисления, остаток долга, график и точные поля |
| Поступившие платежи | Пункт меню | Это входящие оплаты или выплаты студенту; нельзя автоматически считать стипендией |
| Приказы | Пункт меню | Дата, номер, тип, доступность файлов приказов |
| Группы студента | Учебная, лабораторная и факультетские группы | Список участников, контакты и староста при раскрытии |

Сохранённый [лист публичных экранов](../design/research/grsu-apps/mygrsu-store.png) позволяет увидеть основания. Изображения принадлежат издателю приложения и используются как исследовательские референсы. ФИО из этих снимков в демонстрационные профили Kupala Hub переносить не нужно.

## 3. Учебные материалы: потенциальный отдельный источник Moodle

Эти данные не следует приписывать MyGRSU: они относятся к другой системе. По [документации Moodle](https://docs.moodle.org/dev/Web_service_API_functions) существуют функции для курсов, содержимого, заданий и участников. Проверенные публичные настройки edu.grsu.by показывают включённые Web Services и браузерный вход. Однако пользовательский запрос токена вернул invalidlogin; успешного чтения из аккаунта не было.

| Потенциальные данные | Что планировать при получении доступа | Уверенность для ГрГУ |
| --- | --- | --- |
| Собственные курсы | Название, ID, запись пользователя на курс | Гипотеза до чтения разрешённого метода |
| Разделы и материалы | Структура курса, страницы, ссылки, файлы | То же; некоторые материалы могут требовать отдельного доступа |
| Задания | Название, описание, срок сдачи | То же; наличие функции не гарантирует заполненный срок |
| Сдача работы | Статус, дата, отзыв, оценка | То же; не равнозначно итоговой аттестации университета |
| Календарные события | Учебные сроки и события курса | То же; не замена расписанию API |
| Участники курса | Доступные имена и роли | То же; не официальный состав учебной группы |

## 4. Что не подтверждено даже как функция изученных приложений

- Старосты, заместители, срок полномочий и достоверные контакты.
- Полный официальный список студентов группы и подтверждённое членство.
- Стипендия и другие выплаты студенту как отдельный источник. Название «Поступившие платежи» этого не доказывает.
- Задолженность за общежитие, учебные допуски, официальный рейтинг и точные правила назначения выплат.
- Фактическое местоположение преподавателя или студента.
- Полный фонд помещений, вместимость, оснащение, внеучебное бронирование и гарантированная свобода аудитории.

Часть этого упоминалась в исходном ТЗ. До появления конкретного источника это пожелания, а не подтверждённые возможности получения данных.

## 5. Возможности, которые создаём сами

| Возможность | Основа |
| --- | --- |
| Текущая/следующая пара, интервалы, обратный отсчёт | Время, расписание, выбранные подгруппы |
| Изменения и уведомления | Собственные снимки; не история до начала наблюдения |
| Поиск экзаменов и консультаций | Типы событий в расписании |
| Личные задачи, заметки, напоминания | Данные, введённые пользователем |
| Общие задания и объявления | Внутреннее сообщество; отдельное подтверждение роли старосты |
| ICS, печать, закладки, кэш | Генерация и хранение в Kupala Hub |
| Занятость по доступным расписаниям | Производный индекс с указанием покрытия, без обещания фактической свободы |
| Маршрут до корпуса | Адрес + отдельные координаты/карты |

## База для дальнейшего планирования

1. **Ближайший этап с реальными данными:** улучшать текущие экраны, добавить справочник/расписание преподавателей и отдельное представление сессии. Источники для них проверены.
2. **Закрытые учебные модули на будущее:** профиль, пропуски, аттестация, успеваемость и принадлежность к подгруппам. Есть основания по MyGRSU; реализацию автоматической синхронизации оценивать только после получения рабочего доступа.
3. **Отдельная очередь на уточнение:** оплата, платежи и приказы. Пока достаточно зафиксировать категории, без выдуманной детализации схемы.
4. **Потенциальная Moodle-интеграция:** курсы, материалы, задания и сдача — отдельный адаптер после проверки SSO/токена.
5. **Студенты и старосты:** пока собственные приглашения и подтверждённые роли внутри приложения; официальную синхронизацию не обещать.

Для неподключённого модуля хранить статус источника и показывать «не подключено». Если делаем демонстрацию, она остаётся явно обозначенной. Не создавать новые рабочие разделы только потому, что их название присутствует в этом каталоге: он задаёт направления и основания, а не утверждает расширение текущего объёма разработки.
