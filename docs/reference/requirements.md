ТЗ: студенческий помощник ГрГУ

Nov 9, 2026 · @artsiom

Резюме

Kupala Hub (рабочее название) — неофициальное веб-приложение (PWA) для студентов ГрГУ имени Янки Купалы. Оно собирает расписание, учёбу, дедлайны и новости в одном месте и добавляет ИИ-ассистента, который отвечает на вопросы по данным самого студента.

Сейчас информация разбросана. Расписание отдают публичный API и сайт расписания, а также два мобильных приложения, из которых официальное не обновлялось с 2021 года. Оценки, пропуски и оплата живут в личном кабинете MyGRSU (3,3★ в Google Play). Учебные материалы лежат на Moodle-платформе edu.grsu.by. Уведомлений об изменениях расписания в официальных приложениях нет, веб-версии с офлайн-режимом нет, ИИ нет нигде.

Публичный API api.grsu.by (расписание, справочники) используется по максимуму. Закрытые данные — оценки, пропуски, оплата, ЭУМК — в демо заменяются тестовыми данными через те же интерфейсы-адаптеры, чтобы позже подключить реальные источники без переписывания интерфейса.

Ключевые возможности:

«Сегодня» — текущая и следующая пара, окна, успеваешь ли дойти до другого корпуса.

Расписание группы, преподавателя и аудитории: офлайн, экспорт в календарь, уведомления об изменениях.

Кампус — поиск свободной аудитории, «где сейчас преподаватель», адреса корпусов.

Учёба (демо) — оценки, пропуски, аттестация, прогноз стипендии, дедлайны и материалы.

Планировщик — задачи и заметки, привязанные к парам; Telegram-бот для напоминаний.

ИИ-ассистент с инструментами: отвечает по расписанию и успеваемости, строит план подготовки к сессии, объясняет материалы и делает тесты.

Анализ экосистемы ГрГУ

Открыто доступно только расписание: у него есть публичный JSON API без авторизации. Всё персональное (оценки, пропуски, оплата, материалы) закрыто логином, и публичного API к нему нет.

По данным статьи 2016 года, личный кабинет показывает текущую и промежуточную аттестацию, начисленную стипендию, задолженность по оплате обучения и общежития, пропуски. ЭУМК дисциплины состоит из программы, теоретического, практического, контрольного и вспомогательного блоков. Эти структуры берём за основу демо-модели.

API расписания

Базовый адрес — https://api.grsu.by/1.x/app1/, ответы в JSON, даты в формате dd.MM.yyyy. Два метода подтверждены по исходному коду открытого клиента grsu-notifications; остальные известны по сторонним клиентам и проверяются на первой неделе проекта.

| Метод | Параметры | Возвращает | Статус |
| --- | --- | --- | --- |
| getStudent | login | Объект студента с id (и ФИО, группой — проверить) | Подтверждён |
| getGroupSchedule | studentId или groupId, dateStart, dateEnd | days[]: date, lessons[]: timeStart, timeEnd, title, type, teacher.fullname, address, room | Подтверждён (studentId); groupId — проверить |
| getDepartments | — | Формы получения образования | Проверить |
| getFaculties | — | Факультеты | Проверить |
| getGroups | departmentId, facultyId, course | Группы | Проверить |
| getTeachers | extended | Преподаватели, должности, контакты | Проверить |
| getTeacherSchedule | teacherId, dateStart, dateEnd | Расписание преподавателя | Проверить |
| Параметр lang | ru / be / en | Локализованные названия | Проверить |

Ограничения API, которые определяют архитектуру:

Нет авторизации. getStudent по логину отдаёт id без пароля, поэтому логин портала не подтверждает личность. Для закрытых модулей нужна своя аутентификация.

Нет вебхуков и истории. Изменения расписания видны только при сравнении снимков; grsu-notifications опрашивает API раз в 30 минут и строит дифф.

Нет документированных лимитов и SLA. Обязательны кэш и бережный опрос, чтобы не нагружать сервер университета.

Нет данных о сессии, оценках, аудиторном фонде. Сессия — проверить, отдаёт ли её getGroupSchedule за период экзаменов; аудитории выводим из поля room.

В рамках анализа API напрямую не опрашивался: структура ответов взята из кода клиента.

Пробелы, которые закрывает проект:

Нет единой точки входа: расписание, оценки, материалы и новости — в разных местах.

Нет веб-версии с офлайном и установкой на телефон (PWA).

Нет уведомлений об изменениях в официальных приложениях.

Нет поиска свободных аудиторий и «где сейчас преподаватель».

Нет планировщика и дедлайнов, связанных с парами.

Нет ИИ-помощника, который понимает контекст конкретного студента.

Цели, аудитория и сценарии

Главная цель — чтобы студент получал ответ на любой учебный вопрос дня за один экран или одну реплику ассистенту, не переключаясь между сайтами.

Цели и измеримые результаты

| Цель | Метрика | Целевое значение для демо |
| --- | --- | --- |
| Быстро узнать, где и что сейчас | Время от открытия до ответа «где следующая пара» | ≤ 3 с, 0 переходов |
| Не пропускать изменения | Задержка уведомления после изменения в API | ≤ 30 мин |
| Работать без сети | Доступность расписания офлайн | Текущая и следующая неделя |
| Полезный ИИ | Доля верных ответов на тестовом наборе из 100 вопросов | ≥ 90% |
| Полезный ИИ | Доля ответов с выдуманными фактами | ≤ 2% |
| Показать потенциал API | Доля методов API, задействованных в интерфейсе | 100% подтверждённых методов |

Ключевые сценарии

Студент вводит логин портала или выбирает факультет, курс и группу — и сразу видит расписание на сегодня.

Утром приходит сводка: пары, окна, дедлайны, изменения с вечера.

В расписании появилось изменение — через ≤ 30 минут пуш и подсветка изменённой пары.

В окне студент ищет свободную аудиторию рядом с текущей парой.

Студент находит преподавателя и видит, где у того сейчас пара.

Перед сессией ассистент строит план подготовки по датам экзаменов, оценкам и окнам.

Студент загружает лекцию или открывает тему ЭУМК — ассистент делает краткий конспект и тест на 10 вопросов.

Студент спрашивает «сколько ещё можно пропустить» или «хватит ли баллов на стипендию» — ассистент считает по демо-данным и правилам, ссылаясь на источник.

Староста публикует объявление — его видят все в группе, у кого установлено приложение.

1. Профиль и онбординг

ФТ-1.1 Регистрация по email или через Telegram Login. Привязка к студенту — по логину портала (getStudent → studentId) или выбором: форма обучения → факультет → курс → группа.

ФТ-1.2 Избранное: несколько групп и преподавателей с быстрым переключением.

ФТ-1.3 Подгруппа и иностранный язык — фильтр «показывать только мои пары».

ФТ-1.4 Язык интерфейса ru / be / en, светлая и тёмная тема, часовой пояс Europe/Minsk.

ФТ-1.5 Вход в демо без регистрации — готовый профиль «демо-студент».

2. Расписание

ФТ-2.1 Режимы «день», «неделя», «список на месяц»; свайп между днями, автопрокрутка к текущей паре.

ФТ-2.2 Карточка пары: предмет, тип занятия цветом, время, преподаватель, адрес корпуса, аудитория, подгруппа.

ФТ-2.3 Переходы из карточки: к расписанию преподавателя, к аудитории, к материалам дисциплины, к задачам по ней.

ФТ-2.4 Расписание любой группы, преподавателя и аудитории.

ФТ-2.5 Экспорт: ICS-подписка для Google и Apple Calendar, ссылка «поделиться», печать недели в PDF.

ФТ-2.6 Офлайн: текущая и следующая неделя в кэше, метка «данные от ЧЧ:ММ».

ФТ-2.7 Окна и переходы: подсветка окна; предупреждение, если следующая пара в другом корпусе и перерыва не хватает на дорогу пешком.

3. Изменения и уведомления

ФТ-3.1 Фоновый опрос API только для групп активных пользователей: раз в 30 мин с 7:00 до 22:00, раз в 2 ч ночью.

ФТ-3.2 Дифф снимков: пара добавлена, удалена, изменены время, аудитория или преподаватель. Экран «Что изменилось» и подсветка в расписании.

ФТ-3.3 Каналы: Web Push, Telegram-бот, лента в приложении; тихие часы.

ФТ-3.4 Напоминание за N минут до пары, N настраивается.

4. Преподаватели

ФТ-4.1 Справочник с поиском по ФИО и кафедре.

ФТ-4.2 Профиль: должность и контакты (если отдаёт API), дисциплины у моей группы.

ФТ-4.3 «Где сейчас»: текущая и следующая пара преподавателя.

ФТ-4.4 Часы консультаций — демо.

5. Аудитории и кампус

ФТ-5.1 Индекс аудиторий строится ночной задачей обходом расписаний всех групп за неделю; ключ — «адрес + номер».

ФТ-5.2 Поиск свободной аудитории по корпусу и времени с пометкой «по расписанию, без учёта мероприятий».

ФТ-5.3 Справочник корпусов: адрес, координаты, фото, время пешком между корпусами, кнопка маршрута в картах.

ФТ-5.4 Карта кампуса с отметками «сейчас идёт пара» — v2.

6. Сессия

ФТ-6.1 Зачёты, экзамены и консультации — из API, если он отдаёт период сессии, иначе демо.

ФТ-6.2 Экран «Сессия»: обратный отсчёт, допуск, список зачётов и экзаменов.

ФТ-6.3 План подготовки от ассистента (раздел «ИИ-агент»).

7. Успеваемость и посещаемость (демо)

ФТ-7.1 Текущая и промежуточная аттестация по дисциплинам, рейтинг.

ФТ-7.2 Пропуски: уважительные и неуважительные, по дисциплинам, динамика.

ФТ-7.3 Калькулятор среднего балла и режим «что если»: какие отметки нужны для порога стипендии. Правила — в конфиге, а не в коде.

ФТ-7.4 Риск-флаги (много пропусков, низкая отметка) с подсказкой ассистента.

8. Финансы (демо)

ФТ-8.1 Оплата обучения: начислено, оплачено, задолженность, сроки.

ФТ-8.2 Стипендия, выплаты, оплата общежития.

ФТ-8.3 Напоминания о сроках оплаты. Платежи приложение не проводит.

9. Материалы и задания (демо, затем Moodle)

ФТ-9.1 Курсы семестра; блоки ЭУМК: программа, теория, практика, контроль знаний, вспомогательный блок.

ФТ-9.2 Задания с дедлайном, статусом сдачи и отметкой.

ФТ-9.3 Свои файлы к паре (конспект, фото доски, PDF) — индексируются для ассистента.

ФТ-9.4 Вопросы к зачёту и экзамену.

10. Планировщик

ФТ-10.1 Задача с дедлайном, приоритетом и привязкой к дисциплине или паре. «К следующему занятию» — дата вычисляется по расписанию.

ФТ-10.2 Заметки к конкретной паре.

ФТ-10.3 Повторяющиеся задачи и чек-листы.

ФТ-10.4 Задачи видны в «Сегодня» и в сетке расписания.

11. Новости и события

ИИ-агент «Ассистент»

Ассистент — агент с вызовом инструментов (function calling): он отвечает только на основе данных приложения и документов университета, а не «из головы». Каждый факт в ответе ссылается на источник — пару, документ или демо-запись.

Принципы

Сначала инструмент, потом ответ. Расписание, оценки, правила модель берёт через инструменты; без данных — честно говорит «не знаю» и даёт, куда обратиться.

Только чтение по умолчанию. Создать задачу, напоминание или черновик письма можно лишь после подтверждения в карточке действия.

Наставник, а не исполнитель. Объясняет, задаёт наводящие вопросы, делает тесты; не пишет за студента работы под сдачу и не решает контрольные.

Язык пользователя. Отвечает на ru / be / en, иностранным студентам — простыми фразами.

Демо видно. Если ответ опирается на демо-данные, это помечается в ответе.

Сценарии

«Где следующая пара и успею дойти?» → get_now_next: предмет, корпус, аудитория, время пешком и вердикт.

«У меня окно, где позаниматься?» → find_free_rooms рядом с текущим корпусом.

«Составь план подготовки к сессии» → get_exams + get_grades + get_schedule (окна) → план по дням, слабые предметы первыми; по согласию — create_task на каждый день.

«Объясни тему из ЭУМК и проверь меня» → search_materials + generate_quiz, разбор ошибок.

«Что поменялось в расписании на неделе?» → get_schedule_changes.

«Хватит ли баллов на стипендию?» → calc_scholarship_scenario + search_regulations, с пометкой «демо, уточните в деканате».

«Напиши преподавателю, что я болею» → find_teacher + draft_message.

Устройство

Цикл агента: системный промпт с контекстом студента (группа, подгруппа, язык, текущее время Europe/Minsk) → модель выбирает инструменты → бэкенд выполняет их с правами пользователя → ответ со ссылками. Не более 6 вызовов инструментов за ход.

Память: краткосрочная — диалог; долгосрочная — явные факты профиля (подгруппа, предпочтения), которые пользователь видит и может удалить.

RAG: чанки 500–800 токенов, мультиязычные эмбеддинги (например, bge-m3), pgvector, гибридный поиск (полнотекст + вектор) с переранжированием.

Модель: через шлюз с OpenAI-совместимым интерфейсом (например, LiteLLM), чтобы менять провайдера без правки кода. Варианты: облачная модель с сильным function calling — при условии доступности из Беларуси и допустимости передачи данных; либо открытая модель 7–32B (семейства Qwen или Llama) на своём сервере через vLLM или Ollama. Дешёвая модель — для коротких сводок и маршрутизации.

Безопасность и качество

userId инструменты берут из сессии, а не из текста модели: чужие данные недоступны.

Тексты документов, новостей и файлов — данные, а не инструкции (защита от prompt injection); запись — только через подтверждение.

В облачную модель уходит минимум персональных данных; диалоги хранятся 30 дней и только с согласия.

Лимиты: сообщений в день на пользователя и токенов на запрос; кэш частых ответов.

Оценка: набор из 100 вопросов с эталонами прогоняется в CI; метрики — точность, верный выбор инструмента, доля выдуманных фактов, задержка p95 ≤ 8 с; трассировка запросов (например, Langfuse).

Реалистичность. Генератор берёт реальные названия дисциплин и типы занятий из расписания группы, а оценки, пропуски и платежи создаёт по правдоподобным распределениям.

Детерминизм. Генерация с фиксированным seed от studentId: на каждом показе одни и те же данные.

Персоны. Готовые профили: «отличник», «должник», «заочник в сессию», «первокурсник».

Нет чужих персональных данных. В демо-оценках и демо-платежах нет реальных ФИО других студентов.

Видимость. Каждый экран и ответ ассистента с демо-данными несёт пометку «Демо».

Формат как в оригинале. Структуры повторяют разделы личного кабинета и блоки ЭУМК, чтобы замена на реальный источник была механической.

Архитектура и стек

PWA-клиент обращается только к своему бэкенду; бэкенд ходит в API ГрГУ через кэш и адаптеры, а фоновый воркер опрашивает расписание и рассылает уведомления. Клиент никогда не обращается к api.grsu.by напрямую — так сохраняются кэш, лимиты и единая модель данных.

архитектура · клиенты, сервер, интеграции, хранилища

Студент работает через PWA или Telegram-бот; бэкенд и воркер получают данные только через слой интеграций, а ИИ-сервис берёт данные студента через инструменты бэкенда и обращается к модели через шлюз.

Компоненты

Веб-клиент (PWA) — интерфейс, офлайн-кэш, Web Push, стрим ответов ассистента по SSE.

Backend API — REST, аутентификация, бизнес-логика модулей, права доступа.

Слой интеграций — провайдеры GrsuApiProvider, RaspisanieScraper (резерв), DemoProvider, позже MoodleProvider; единые модели данных.

Воркер — опрос API и диффы, индекс аудиторий, сводки, рассылки, индексация документов.

ИИ-сервис — цикл агента, инструменты, RAG, шлюз к модели.

Telegram-бот — уведомления, сводки и короткие вопросы ассистенту.

Хранилища — PostgreSQL с pgvector, Redis, S3-совместимое хранилище файлов.

Работа с API ГрГУ

Кэш расписания в Redis на 15 минут; один запрос на группу за период, сколько бы студентов её ни смотрели.

Ограничение исходящих запросов: не больше 2 в секунду, экспоненциальная повторная попытка, circuit breaker.

При недоступности API — последний снимок из БД с меткой времени, затем резервный парсер raspisanie.grsu.by.

Даты в запросах — dd.MM.yyyy, часовой пояс Europe/Minsk; ответы валидируются схемой, неизвестные поля логируются.

Критерии приёмки

☐ Новый пользователь за ≤ 60 с привязывает группу и видит расписание на сегодня.

☐ Все подтверждённые методы API задействованы в интерфейсе; при недоступности API виден последний снимок с меткой времени.

☐ Изменение расписания приходит пушем и в Telegram не позже чем через 30 мин (в демо-сценарии — сразу).

☐ Расписание текущей и следующей недели открывается в авиарежиме.

☐ ICS-подписка добавляется в Google Calendar и обновляется.

☐ Ассистент верно отвечает на ≥ 90% тестовых вопросов, выдуманных фактов ≤ 2%, у каждого факта есть источник.

☐ Действия ассистента с записью выполняются только после подтверждения.

☐ Все демо-данные помечены; переключатель источника работает для каждого модуля.

☐ Lighthouse: Performance ≥ 85, Accessibility ≥ 90, приложение устанавливается как PWA.

☐ Интерфейс полностью переведён на русский, белорусский и английский.

☐ Пользователь может удалить аккаунт и все свои данные.

Риски

Главные риски — ошибки ассистента в вопросах правил и отсутствие согласования с университетом. Оба снижаются с первого этапа: инструменты и ссылки вместо «знаний модели», статус неофициального проекта и письмо в университет.

| Риск | Вероятность | Влияние | Снижение |
| --- | --- | --- | --- |
| API ГрГУ меняется или отключается | Средняя | Высокое | Валидация схемы, снимки в БД, резервный парсер, алерт на ошибки |
| Ассистент ошибается в правилах, пропусках, стипендии | Высокая | Высокое | Инструменты и поиск по официальным документам, ссылки на источник, пометка «уточните в деканате», тестовый набор в CI |
| Нет согласия университета на использование данных, названия и логотипа | Средняя | Высокое | Статус «неофициальное приложение», без логотипа; письмо в информационно-аналитический центр с предложением сотрудничества |
| Провайдер модели недоступен из Беларуси или дорог | Средняя | Высокое | Шлюз с OpenAI-совместимым интерфейсом, запасной вариант — своя открытая модель, бюджетные лимиты |
| Нарушение требований к персональным данным | Средняя | Высокое | Согласие, минимизация, удаление по запросу, минимум данных во внешние сервисы, юридическая проверка перед запуском для реальных пользователей |
| getStudent отдаёт id по логину без пароля — можно выдать себя за другого | Средняя | Среднее | Логин портала только для публичного расписания; персональные данные — только через свою аутентификацию |
| Ассистент используют для списывания | Средняя | Среднее | Режим наставника в системных правилах, тесты на отказ в наборе оценки |
| Демо-данные принимают за реальные | Средняя | Среднее | Значок «Демо» на экранах и в ответах, отдельный демо-стенд |
| Приложение нагружает сервер университета | Низкая | Высокое | Кэш, один запрос на группу, ≤ 2 запроса/с, опрос только активных групп |
| Инъекция инструкций через документы и новости | Низкая | Среднее | Тексты — данные, а не команды; запись только с подтверждением |

Не входит в проект: распознавание лиц и фотоконтроль посещаемости, приём платежей, запись данных в системы университета.
