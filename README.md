# Kupala Hub

Десктопное веб-приложение для студентов ГрГУ: учебный день, расписание, задачи и пространство группы. Интерфейс основан на выбранном макете A «Ясный день».

## Запуск

Нужен Node.js 22.13+ (рекомендуется поддерживаемая LTS-версия) и npm. Используется встроенный модуль `node:sqlite`; отдельный сервер базы данных не требуется.

```bash
npm ci
npm run dev
```

Открыть http://localhost:5173. API работает на http://127.0.0.1:3001. Процессы запускаются одной командой. При наличии `.venv` запускается также Python-сервис ассистента. Остановка — Ctrl+C.

Собранная версия с одним сервером:

```bash
npm run build
npm start
```

Открыть http://localhost:3001. Сервер по умолчанию слушает только локальный компьютер.

## Возможности

- Выбор формы обучения, факультета, курса и группы из публичного API ГрГУ.
- «Сегодня»: занятия, интервалы между ними и личные задачи.
- Расписание на семь дней, дневной режим, выбор даты, фильтр подгрупп, подробности занятия.
- Загрузка расписания через сервер, кэш в SQLite, дата снимка и предупреждение при недоступности источника. Первичная загрузка реальных данных требует сети.
- Сравнение снимков одной недели: добавление, исчезновение, изменение места или преподавателя. Истории до первого снимка нет. Фоновое обновление каждые 15 минут происходит, пока страница открыта.
- Экспорт выбранной недели и подгрупп в ICS.
- Создание, редактирование, поиск, фильтры, завершение и удаление личных задач. День работы и срок сдачи задаются отдельно.
- Гостевой профиль в cookie; создание отдельного аккаунта Kupala Hub сохраняет его задачи. Вход с другого браузера открывает задачи аккаунта. При входе в существующий аккаунт гостевые задачи не переносятся автоматически.
- Демо-расписание, явно отделённое от реального. Задачи демо имеют отдельную область хранения.

## Расширение разделов

Расширение сохраняет дизайн A и группирует навигацию: «Мой день», «Учёба», «Университет», «Личное».

- **Преподаватели:** поиск по публичному каталогу, заполненные контакты и недельное расписание, сохранённые избранные.
- **Сессия:** экзамены, зачёты, консультации и защиты из расписания выбранной недели; полнота публикации не гарантирована, официального допуска и результатов здесь нет.
- **Кампус:** корпуса и аудитории, встречающиеся в расписании выбранной группы, внешние карты и фактический охват. Отсутствие занятия в этой выборке не означает свободу помещения.
- **Успеваемость:** оценки, аттестация, пропуски — отдельные страницы с состоянием неподключённого источника и явно включаемыми вымышленными примерами.
- **Материалы:** университетские курсы/задания пока не подключены; собственные ссылки и текстовые заметки сохраняются и редактируются в Kupala Hub. Бинарные файлы не загружаются на сервер.
- **Платежи и документы:** оплата, поступления и приказы представлены отдельными примерами, без реальных финансовых данных, проведения оплаты и несуществующих PDF.
- **Сообщество:** создание пространства, присоединение по приглашению, объявления, общие задания, опросы и голосование. Организатор управляет пространством и приглашениями; эта роль не является подтверждением официального статуса старосты. Члены пространства — пользователи Kupala Hub, не официальный контингент университета.
- **Профиль и настройки:** собственные имя, контакт, описание и предпочтения. Университетская личность не подтверждается выбором группы.

Демо и live отделены в API и хранилище; пример закрытого раздела не переключает реальные задачи пользователя. Схемы SQLite расширяются без удаления существующих задач и аккаунтов.

**ИИ-ассистент:** отдельный Python/FastAPI-сервис с `deepseek-flash` через прокси `llm.azati.ai`, как в `project-matcher`, с контекстом задач, расписания и заметок, историей и предложениями изменения задач с подтверждением. Для работы нужен ключ прокси с доступом к flash; [настройка и ограничения](docs/assistant.md).

Автоматическая интеграция с личным кабинетом/Moodle, Web Push, полная автономная работа без сети и мобильная раскладка пока не подключены. При сбое ГрГУ кэш доступен через работающий сервер; это не офлайн-кэш всего приложения в браузере. Восстановление пароля и подтверждение email пока отсутствуют.

## Данные и настройки

Проверка образовательного портала со своим аккаунтом: `npm run check:portal`. Пароль вводится скрыто; подробности и формат безопасного отчёта — в [инструкции](docs/portal-check.md). Это диагностическая команда, автоматическая синхронизация в интерфейсе ещё не подключена.

Файл `data/kupala.sqlite` создаётся автоматически; задачи, настройки, аккаунты, серверные сессии и кэш переживают перезапуск. Не удаляйте `data/`, если хотите сохранить данные. Для резервной копии остановите сервер и скопируйте каталог целиком. Файл БД содержит личные данные и хеши паролей; он не должен публиковаться.

Переменные окружения можно задать перед командой запуска или в `.env`. Пример перечислен в `.env.example`. `npm start`, `npm run dev` и `npm run start:agent` читают `.env` автоматически. Явный запуск API:

```bash
node --env-file=.env server/index.js
```

- `PORT`, `HOST`: адрес сервера (по умолчанию 3001 и 127.0.0.1).
- `DB_PATH`: путь к SQLite, по умолчанию `data/kupala.sqlite`.
- `APP_ORIGIN`: список разрешённых источников изменения данных через запятую, без завершающего `/`. Для собственного адреса его нужно указать явно.
- `COOKIE_SECURE=true`: включать за HTTPS перед размещением.

Аккаунт приложения отделён от университетского. Пароли хешируются scrypt с индивидуальной солью; session-cookie HttpOnly, SameSite=Lax; изменяющие запросы требуют CSRF-токен; доступ к задачам проверяется по владельцу. Предусмотрены лимиты запросов и проверка входных данных. Для публичного запуска ещё нужны почтовое восстановление, подтверждение email, проверка развёртывания и отдельный аудит безопасности.

## Проверка

```bash
npm test
npm run build
npm run lint
npm run format:check
```

`npm run lint` проверяет JS/JSX правилами ESLint, `npm run format` переформатирует код Prettier, `npm run format:check` проверяет форматирование без изменений. Конфигурация — `eslint.config.js`, `.prettierrc.json`; сгенерированные каталоги и `docs/` в форматирование не входят.

Тесты покрывают сессии, CRUD и принадлежность задач, демо-изоляцию, регистрацию/вход/выход, перезапуск SQLite, время Минска, подгруппы, валидацию и поведение кэша при сбоях. Добавлены проверки преподавателей, событий сессии, материалов, сообществ, приглашений, ролей и голосования. Итого 36 предметных проверок в пяти файлах, включая 7 проверок ассистента (в этой среде `npm test` группирует результат по файлам). Python-сервис проверяется отдельно: `npm run test:agent` после установки зависимостей.

Начальная виртуальная браузерная проверка описана в `docs/implementation/verification.md`. Она относится к первой версии. Для расширения 23.11.2026 сборка и API-тесты прошли, независимый review завершён: [отчёт](docs/implementation/expansion-review.md). **Новая браузерная приёмка заблокирована средой и не считается пройденной:** [подробности](docs/implementation/expansion-ui-check.md). Публичные источники и бизнес-логика проверялись отдельно; это не заменяет проверку форм и раскладок в браузере.

План расширения и дизайн: `docs/implementation/expansion-plan.md`, `docs/implementation/expansion-design.md`. [Визуальный прототип](design/expansion/preview.html) — эскиз направления, а не скриншот рабочей версии.

## Структура

- `server/` — Fastify API, JavaScript ESM, SQLite и адаптер ГрГУ.
- `ai_service/` — отдельный Python/FastAPI-сервис с DeepSeek, без доступа к SQLite.
- `web/src/` — React, JavaScript/JSX и CSS.
- `shared/calendar.js` — даты, время и фильтрация расписания.
- `tests/` — серверные и предметные тесты на `node:test`.
- `public/fonts/` — локальный Onest и лицензия OFL.
- `design/` — исходные референсы и макеты.
- `docs/data-feasibility-audit.md` — проверенные источники данных и ограничения.
- `docs/grsu-data-catalog.md` — каталог данных других приложений ГрГУ и возможных направлений развития.

Стек текущей версии: React 19, Vite 7, Fastify 5, SQLite; микросервис ИИ — Python/FastAPI/httpx. Бизнес-бэкенд написан на JavaScript. Предыдущая спецификация с Next.js/PostgreSQL/Redis сохранена как история предложений; действующее состояние описано здесь.
